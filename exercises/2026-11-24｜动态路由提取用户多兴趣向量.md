# 2026-11-24｜动态路由提取用户多兴趣向量

## 1. 任务背景

DIN 会针对一个候选商品，从用户历史中聚合出一个候选相关兴趣；MIND 则希望先把用户的行为序列拆成多个兴趣胶囊，例如“生鲜”“母婴”“运动”三个方向，再让候选商品匹配其中最相关的兴趣。

本练习聚焦 MIND 中最有代表性的动态路由过程：每条历史行为在多个兴趣胶囊之间分配权重，胶囊根据当前聚合结果与行为投票向量的一致程度反复更新分配。你需要处理补齐位置和完全空历史，并保证路由权重、向量范数与输出形状正确。

预计用时：20–30 分钟。

## 4. 待完成任务

1. 实现 `squash`：
   - 在指定维度计算向量平方范数；
   - 保留输入维度以支持广播；
   - 将向量方向保留、长度压缩到小于 1；
   - 对零向量和极小范数保持数值稳定。

2. 实现 `DynamicInterestRouter.forward`：
   - 将 `[B, T, D]` 行为向量与 `[K, D, D]` 投影矩阵组合成 `[B, T, K, D]`；
   - 路由 softmax 必须沿兴趣维 `K` 计算，而不是时间维 `T`；
   - 每轮按权重聚合投票向量并应用 `squash`；
   - 非最后一轮根据投票向量与兴趣向量的点积更新 logits；
   - 遮蔽位置不得影响兴趣向量或后续路由更新。

3. 实现 `MultiInterestModel.forward`：
   - 查询 embedding 并调用路由模块；
   - 计算每个候选商品与 `K` 个兴趣的匹配分数；
   - 使用最高匹配分数作为当前候选得分；
   - 返回得分及被选中的兴趣编号。

4. 处理边界情况：
   - 空历史的路由权重与兴趣向量必须全为 0；
   - 所有张量必须保持有限；
   - 不允许通过删除空历史样本或放宽断言绕过问题。

5. 运行全部检查，并打印每个样本选择的兴趣编号。观察具有不同历史长度的用户是否都能得到合法输出。
