# 2026-10-13｜Beta平滑冷启动商品转化率

## 1. 任务背景

昨天你用配对 Bootstrap 判断新召回模型的整体 Recall 提升是否稳定。模型通过整体评估后，运营还需要决定优先曝光哪些商品，但直接按“下单数 ÷ 曝光数”排序会严重偏爱小样本商品：一个只曝光 1 次且恰好成交的商品，原始转化率会达到 100%。

今天使用 Beta-Binomial 平滑处理商品转化率：

1. 从全体历史数据估计平均转化率；
2. 用“先验强度”把平均转化率转换为 Beta 先验参数；
3. 将每个商品的曝光数和下单数更新为后验分布；
4. 计算后验均值，降低小样本极端值的影响；
5. 用后验转化率估计下一周期的期望销量。

练习会特别处理零曝光冷启动商品、非法计数和确定性排序。预计完成时间：20–30 分钟。

## 4. 待完成任务

1. 实现 `validate_counts`：
   - 四个数组都必须是一维、非空且长度一致。
   - 商品 ID 必须唯一。
   - 三个计数数组必须是整数类型且所有值非负。
   - 每个商品都必须满足 `orders <= impressions`。

2. 实现 `estimate_beta_prior`：
   - `prior_strength` 必须是有限正数。
   - 全局曝光总数必须大于 0。
   - 全局转化率使用 `orders.sum() / impressions.sum()`。
   - 返回正数 `alpha0` 和 `beta0`，并保证二者之和等于 `prior_strength`。
   - 如果全局转化率恰好为 0 或 1，应抛出 `ValueError`，避免产生退化先验。

3. 实现 `beta_posterior_summary`：
   - 使用
     `alpha_post = alpha0 + orders`。
   - 使用
     `beta_post = beta0 + impressions - orders`。
   - 后验均值为
     `alpha_post / (alpha_post + beta_post)`。
   - 原始转化率只对曝光数大于 0 的商品计算；零曝光商品设为 `np.nan`。
   - 不修改输入数组。

4. 实现 `rank_products`：
   - 先按后验均值降序排序。
   - 后验均值相同时，按商品 ID 字典序升序排序。
   - 返回排序后的商品 ID，不返回数组索引。

5. 实现 `expected_sales`：
   - 两个输入必须是一维且 shape 一致。
   - 后验均值必须是有限值，并位于闭区间 `[0, 1]`。
   - 未来曝光量必须是非负整数。
   - 返回浮点数数组 `posterior_mean * future_impressions`。

6. 用断言完成自检：
   - `alpha0 + beta0` 应等于 `PRIOR_STRENGTH`。
   - 每个后验均值都应位于开区间 `(0, 1)`。
   - `sku_F` 的后验均值应等于全局先验均值。
   - 曝光 4 次、下单 1 次的 `sku_D`，平滑后转化率应明显低于原始的 25%。
   - 大样本商品 `sku_A` 的平滑后转化率与原始转化率之差，应小于小样本商品 `sku_D` 的对应差值。
   - 商品排序重复运行两次应完全一致。
   - `sales_forecast` 的 shape 应与 `product_ids` 相同，且所有值非负。
