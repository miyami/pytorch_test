# 2026-10-02｜分批矩阵乘法实现TopK召回

## 1. 任务背景

矩阵分解模型通常用用户向量与商品向量的点积计算召回分数。若一次性计算全部用户与全部商品的得分矩阵，在约 1,876,533 个用户、73,753 个商品、`float32` 的场景下，仅得分矩阵就需要约 **515.6 GiB** 内存，实际程序很容易变慢或崩溃。

今天实现一个**精确、分批、流式写回**的 Top-K 召回器：

1. 按用户切分 batch；
2. 每批执行一次矩阵乘法；
3. 屏蔽用户已经交互的商品；
4. 用 `torch.topk` 取当前批结果；
5. 立即写入预分配结果张量，不保存所有批次的完整得分。

本练习不使用 FAISS，重点是先建立一个容易验证的精确召回基线，并理解 batch size 如何影响峰值内存。

预计完成时间：20–30 分钟。
