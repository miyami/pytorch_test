# 2026-10-29｜梯度范数监控与异常批次跳过

## 1. 任务背景

销量模型训练时，极端脏数据、错误的量纲或数值溢出可能让 loss 或梯度变成 `inf` / `nan`。如果训练循环仍然执行 `optimizer.step()`，一次异常更新就可能污染全部参数，后续很难判断问题来自哪一个批次。

今天你将为一个小型 PyTorch 销量回归模型增加“安全训练”能力：

1. 记录每个参数的梯度 L2 范数、最大绝对值和有限性；
2. 汇总模型的全局梯度范数；
3. 在更新前检查 loss 与梯度；
4. 对正常批次执行梯度裁剪；
5. 对异常批次跳过参数更新，并保留可定位的诊断记录。

数据中故意放入一个仍为有限值、但量级异常大的促销特征。它会使对应批次的 MSE 溢出，从而测试你的保护逻辑。预计完成时间：20–30 分钟。

## 3. 学习目标

完成本练习后，你应该能够：

1. 区分“loss 非有限”和“反向传播后梯度非有限”两类故障。
2. 使用 `named_parameters()` 获取可定位到参数名的梯度诊断信息。
3. 正确计算逐参数梯度范数与模型全局梯度范数。
4. 理解为什么诊断统计应使用 float64，避免统计过程自身溢出。
5. 在 `optimizer.step()` 前使用 `torch.isfinite` 建立保护条件。
6. 使用 `clip_grad_norm_` 裁剪梯度，并比较裁剪前后的范数。
7. 确保异常批次不会修改模型参数，也不会进入 epoch loss。

## 4. 待完成任务

1. 实现 `SalesRegressor.forward`：
   - 执行 `hidden -> ReLU -> output`。
   - 输出 shape 必须为 `[batch_size, 1]`。
   - 不要在回归输出层后增加 ReLU。

2. 实现 `collect_gradient_stats`：
   - 只统计 `grad is not None` 的参数。
   - 每个参数记录 `l2_norm`、`max_abs` 和 `is_finite`。
   - 范数和最大绝对值返回 Python `float`，有限性返回 Python `bool`。
   - 使用 float64 计算各参数平方和，再得到全局 L2 范数。
   - 如果没有任何参数产生梯度，抛出 `RuntimeError`。
   - 统计函数不得修改或清空梯度。

3. 实现 `flatten_parameters`：
   - 对每个参数执行 `detach().reshape(-1)`。
   - 拼接后必须 `clone()`，不能返回仍与模型共享存储的视图。
   - 后续使用 `torch.equal` 比较异常批次前后的参数快照。

4. 实现 `train_one_epoch_safely`：
   - 每批开始调用 `optimizer.zero_grad(set_to_none=True)`。
   - 在前向传播前保存参数快照。
   - 使用 `torch.isfinite(loss)` 判断 loss 是否有限。
   - loss 非有限时禁止调用 `backward()` 和 `optimizer.step()`。
   - loss 有限时执行反向传播并收集裁剪前统计。
   - 若任一梯度非有限，禁止执行参数更新。
   - 仅对有限梯度调用 `clip_grad_norm_`，然后再次统计全局范数。
   - 裁剪后的全局范数应不超过 `max_grad_norm + 1e-6`。
   - 跳过批次后必须确认参数与批次开始前完全一致。
   - `BatchReport.loss` 对非有限值可保留为 `inf` 或 `nan`。
   - 跳过批次的两个梯度范数字段统一记为 `float("nan")`。
   - 只对 `status="updated"` 的批次累计样本加权 loss。

5. 实现 `summarize_reports`：
   - 固定返回三个键：`updated`、`non_finite_loss`、`non_finite_gradient`。
   - 未出现的状态计数为 0。
   - 遇到未知状态时抛出 `ValueError`。

6. 完成自检：
   - 一轮训练共生成 3 条 `BatchReport`。
   - 第 3 个批次应被标记为 `non_finite_loss`，前两个批次正常更新。
   - 状态汇总应为 `{"updated": 2, "non_finite_loss": 1, "non_finite_gradient": 0}`。
   - 所有成功批次的裁剪后全局范数均不超过 5.0。
   - 删除异常样本或将其促销折扣恢复到合理范围后，3 个批次都能完成更新。
