# 2026-10-28｜Trie约束生成商品语义ID

## 1. 任务背景

生成式商品召回会把商品表示为固定长度的语义 ID，例如商品 102 对应 `(0, 1, 0)`。模型在每一层输出一个码字，但如果直接对各层 logits 独立取最大值，可能拼出训练词表中不存在的路径，例如 `(0, 2, 1)`。

今天你将实现一个轻量的约束解码器：

1. 从合法商品语义 ID 构建前缀 Trie；
2. 根据当前前缀查询下一层允许生成的码字；
3. 在 PyTorch logits 上屏蔽非法码字并执行确定性贪心解码；
4. 将完整语义 ID 映射回候选商品；
5. 计算目标商品命中率，并验证约束解码不会产生非法路径。

数据中故意保留一个语义 ID 冲突：`(0, 1, 0)` 同时对应商品 102 和 109。你需要保留全部候选，而不是只返回一个商品。本练习预计完成时间为 20–30 分钟。

## 4. 待完成任务

1. 实现 `validate_sid_index`：
   - `depth` 和 `codebook_size` 必须为正整数。
   - 映射不能为空，所有 SID 必须是长度为 `depth` 的 tuple。
   - 每个码字必须是 `[0, codebook_size)` 内的整数，布尔值不视为合法整数。
   - 每个商品列表必须非空，只包含不重复的正整数商品 ID。
   - 校验函数不得修改输入对象。

2. 实现 `build_sid_trie`：
   - 按 SID 顺序逐层创建整数子节点。
   - 在叶节点用 `TERMINAL` 保存对应商品列表的副本。
   - 不要把冲突 SID 的多个商品压缩成单个商品。
   - 修改返回 Trie 中的商品列表，不应影响 `sid_to_items`。

3. 实现 `allowed_next_codes`：
   - 空前缀应返回根节点允许的 `[0, 1, 2]`。
   - 前缀 `[0]` 应返回 `[0, 1]`。
   - 前缀 `[0, 1]` 应返回 `[0]`。
   - 不存在的前缀以及完整 SID 均返回空列表。
   - 返回结果必须升序且不包含终止标记。

4. 实现 `constrained_greedy_decode`：
   - 校验 logits 为三维浮点 Tensor，shape 与 `DEPTH`、`CODEBOOK_SIZE` 相符，且所有值有限。
   - 逐样本、逐层查询合法下一码字；关键解码循环必须自己完成。
   - 使用布尔 mask 屏蔽非法码字，再在完整词表维度上执行 `argmax`。
   - 分数并列时依靠索引顺序选择较小码字。
   - 不得原地修改输入 logits，也不能事后把无约束结果替换成某条合法 SID。
   - 本题数据的结果应为：
     `[[0, 1, 0], [1, 0, 1], [2, 1, 1]]`。

5. 实现 `lookup_item_candidates`：
   - 将每行解码结果转换为 tuple 查询。
   - `(0, 1, 0)` 必须返回 `[102, 109]`，不能丢失冲突候选。
   - 未知完整 SID 返回空列表。
   - 返回列表应与原始映射解耦。

6. 实现 `hit_rate`：
   - 对每个样本判断目标商品是否存在于对应候选列表。
   - 返回 Python `float`，本题数据应得到 `1.0`。
   - 候选列表与目标列表数量不一致或为空时抛出 `ValueError`。

7. 完成以下自检：
   - 无约束解码得到的三条 SID 均不在合法索引中。
   - 约束解码结果 shape 为 `(3, 3)`、dtype 为 `torch.long`，且每条路径都合法。
   - 将所有非法码字的 logits 再增大，约束解码结果仍不改变。
   - 构造合法码字并列分数，确认始终选择编号较小者。
   - 调用各函数后，`logits`、`sid_to_items` 及其内部列表均保持不变。
