## 1. 任务背景

算法团队申请 GPU 时，经常会遇到两类估算错误：

- 直接用 GPU 理论峰值计算训练时间，忽略实际利用率；
- 只看算力，不检查参数、优化器状态和激活值能否放入显存。

今天你将实现一个简化的训练资源估算器。它根据模型单样本前向计算量、样本数、训练轮数和训练时限，估算总训练量与所需 GPU 卡数；同时根据参数量、批大小和激活值占用，判断当前配置是否能放入单卡显存。

本题不追求精确预测真实训练时间，而是练习资源评估的底层量纲与约束。预计完成时间为 20–30 分钟。

计算约定：

- 训练计算量近似为：`前向 FLOPs × 3`，其中额外两倍用于反向传播；
- `1 TFLOP = 1000 GFLOP`；
- `1 GB = 1024 MB`；
- GPU 有效吞吐为：`理论峰值 TFLOPS × 实际利用率`；
- 混合精度 Adam 训练中，每个参数按 16 Byte 估算模型状态；
- 只允许使用 GPU 的 `usable_memory_ratio` 比例显存；
- 所需卡数必须向上取整，且至少为 1。

- 区分 FLOP、TFLOP 和 TFLOPS，避免把计算总量与计算速度混用；
- 从单样本前向计算量推导整个训练任务的总 FLOPs；
- 用 GPU 理论峰值和利用率估算有效训练吞吐；
- 根据目标完成时间计算最少 GPU 卡数，并正确向上取整；
- 拆分模型状态、激活值和固定工作区的显存占用；
- 识别“算力足够但显存放不下”的资源配置。
