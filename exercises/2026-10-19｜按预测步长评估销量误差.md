# 2026-10-19｜按预测步长评估销量误差

## 1. 任务背景

昨天的简化 PatchTST 已能输出 `[B, H, C]`：批次、未来步长和商品通道。只看所有元素混在一起的平均 MAE，可能掩盖“第 1 天较准、第 7 天明显变差”的问题，也无法判断模型是否真正优于季节性朴素预测。

今天实现一组多步销量预测评估函数：

1. 按预测步长计算 MAE；
2. 按预测步长计算 WAPE，并处理真实销量总和为 0 的情况；
3. 从训练历史计算季节性朴素误差尺度；
4. 计算按步长的 MASE，公平比较不同销量量级的商品；
5. 根据业务重要性对不同预测步长加权汇总。

本练习只处理评估逻辑，不重复 PatchTST 的 patch 切分和 Transformer 前向过程。预计完成时间：20–30 分钟。

## 4. 待完成任务

1. 实现 `validate_forecasts`：
   - 三个输入都必须是三维浮点 Tensor。
   - `prediction` 与 `actual` 的 shape 必须完全一致，布局为 `[B, H, C]`。
   - `history` 的布局为 `[B, L, C]`，其批次和通道数必须与预测一致。
   - 所有 Tensor 必须位于同一 device，全部有限且非负。
   - 历史长度和预测步长都必须大于 0。

2. 实现 `mae_by_horizon`：
   - 计算 `abs(prediction - actual)`。
   - 只沿 batch 维和 channel 维求平均。
   - 返回的一维 Tensor 长度必须等于 `H`。
   - 不得把不同预测步长混在同一个均值中。

3. 实现 `wape_by_horizon`：
   - 分子为每个 horizon 上跨 batch、channel 的绝对误差总和。
   - 分母为同一 horizon 的真实销量总和。
   - 分母为 0 时返回 `torch.nan`，不能返回 `inf`。
   - 输出 shape 必须为 `[H]`。

4. 实现 `seasonal_naive_scale`：
   - `season_length` 必须是正整数且严格小于历史长度。
   - 比较 `history[:, season_length:, :]` 与
     `history[:, :-season_length, :]`。
   - 对绝对差沿历史时间维求均值。
   - 返回 shape 为 `[B, C]`，不能跨样本或通道求平均。

5. 实现 `mase_by_horizon`：
   - `scale` 必须是二维 Tensor，shape 为 `[B, C]`。
   - 仅 `scale > 0` 且有限的位置有效。
   - 将有效尺度扩展到 horizon 维，对每个绝对误差做缩放。
   - 每个 horizon 分别对有效的样本-通道做宏平均。
   - 全部尺度无效时，相应结果返回 `torch.nan`。

6. 实现 `weighted_horizon_score`：
   - 两个输入都必须是一维、非空且长度一致。
   - 权重必须全部有限且非负，总和大于 0。
   - 指标为 `nan` 或 `inf` 的位置不参与计算。
   - 剩余权重必须重新归一化。
   - 没有有效指标时抛出 `ValueError`。
   - 返回 Python `float`。

7. 用断言完成自检：
   - `mae.shape == wape.shape == mase.shape == (4,)`。
   - `scale.shape == (2, 3)`。
   - 所有有限的 MAE、WAPE、MASE 都应非负。
   - 令 `prediction = actual` 时，三个指标的有效位置都应为 0。
   - 同时把预测、真实值和历史销量乘以 10，MAE 应乘以 10，而 WAPE 与 MASE 应保持不变。
   - 只增加第 4 个 horizon 的误差时，前 3 个 horizon 指标不能变化。
   - 将某个历史序列设为常数后，其 scale 为 0，且该序列应被 MASE 排除。
