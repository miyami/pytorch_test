# 2026-11-27｜分解推荐新颖度与流行度偏置

## 1. 任务背景

推荐模型上线后，点击率可能下降，但加购和下单上升。此时只看点击率，很难判断模型是否把用户从熟悉的热门商品带向了更有价值的长尾商品。

“新颖度”常用商品流行概率的自信息来度量：历史中越少见的商品，信息量越高。但高新颖度不一定意味着高质量，也可能只是推荐了大量冷门商品。因此本练习会同时计算列表新颖度、长尾曝光率、列表内重复率和目录覆盖率，并按用户活跃度分组，诊断模型是否存在流行度偏置。

预计用时：20–30 分钟。

## 3. 学习目标

完成本练习后，你应能：

- 用商品历史流行概率的自信息计算推荐列表新颖度；
- 使用加法平滑安全处理目录中从未出现的商品；
- 用累计交互质量定义头部商品集合，而不是随意按商品数量切分；
- 区分列表新颖度、长尾曝光率、重复率和目录覆盖率；
- 按用户分群诊断流行度偏置，避免被总体均值掩盖。

## 4. 待完成任务

1. 实现 `build_item_information`：
   - 对历史交互按商品计数；
   - 以完整商品目录为基准保留零交互商品；
   - 使用 `alpha` 加法平滑，保证所有概率为正且总和为 1；
   - 计算以 2 为底的自信息；
   - 返回普通数值列，不保留临时合并字段。

2. 实现 `mark_long_tail`：
   - 按未平滑交互次数降序排列；
   - 计算历史交互累计占比；
   - 找到覆盖 `head_mass` 所需的最小头部集合；
   - 将其余商品标为长尾；
   - 处理总历史交互数为 0 的边界情况。

3. 实现 `evaluate_user_lists`：
   - 检查每个用户只有一个 segment，rank 不重复且商品都在目录中；
   - 将推荐位置与商品信息连接；
   - 按用户计算新颖度、长尾曝光率和重复率；
   - 每个推荐位置都参与 novelty 与 long-tail 计算，重复商品不能先去重。

4. 实现 `summarize_segments`：
   - 每个用户在分群均值中权重相同；
   - 返回用户数及三个平均指标；
   - 保证输出列顺序固定，结果按 segment 排序。

5. 实现 `catalog_coverage` 并解释结果：
   - 分母使用完整目录商品数；
   - 分子使用所有推荐中出现过的不同合法商品数；
   - 对比三个用户分群的新颖度和长尾率；
   - 判断高新颖度是否伴随更高重复率或更低覆盖率，避免只用单指标下结论。
