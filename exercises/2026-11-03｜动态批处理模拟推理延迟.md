## 1. 任务背景

深度学习在线推理服务通常不会让每个请求单独占用一次 GPU 调用，而是把短时间内到达的请求组成批次。更大的批次能提高吞吐，但会增加排队时间；不同长度请求放在同一批次，还会因 padding 产生额外计算。

今天你将实现一个单 GPU、FIFO 的动态批处理模拟器：

1. 请求按到达时间进入等待队列；
2. 队首请求最多等待 `max_wait_ms`，到期后触发组批；
3. 批次同时受最大请求数和最大填充 Token 数约束；
4. 批处理耗时由固定开销和填充后 Token 数共同决定；
5. GPU 忙碌期间到达的请求继续排队；
6. 最终统计吞吐、批大小、延迟分位数和 padding 效率。

为保持练习可控，本题只模拟单 GPU、单推理阶段，不涉及多实例、并发 CUDA stream 或真实模型执行。预计完成时间为 20–30 分钟。

   - `input_tokens` 必须是正整数，布尔值不视为整数。
   - 每个请求单独成批时都必须满足 `max_padded_tokens`。

   - 批次不能为空。

   - 不能跳过长请求去选择后面的短请求。

   - selected 与 remaining 拼接后应与原 pending 顺序完全一致。
