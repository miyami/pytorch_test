# 2026-10-16｜掩码池化批量生成用户向量

## 1. 任务背景

昨天你用 Python 循环为单个用户聚合商品向量。真实推荐任务通常需要一次处理一批用户，但每个用户的历史长度不同，因此会把序列补齐到统一长度。补齐位置如果参与平均，会把用户向量错误地拉向零向量；如果某个用户整行都是补齐值，还可能产生除零和 `NaN`。

今天使用 PyTorch 实现批量用户向量编码：

1. 用 `0` 表示 padding 商品；
2. 根据商品 ID 构造有效位置掩码；
3. 将行为权重与时间衰减组合成位置权重；
4. 对 `[batch, seq_len, embedding_dim]` 商品向量做 masked weighted pooling；
5. 对空历史用户返回全零向量，并显式标记其无有效历史。

重点是 Tensor shape、广播、掩码和数值安全，不包含模型训练。预计完成时间：20–30 分钟。

## 4. 待完成任务

1. 实现 `validate_batch`：
   - 三个输入都必须是二维 Tensor，且 shape 完全一致。
   - `item_ids` 必须是 `torch.long`，取值位于 `[0, num_items - 1]`。
   - `behavior_weights` 和 `days_ago` 必须是浮点 Tensor，且全部有限、非负。
   - 非 padding 位置的行为权重必须严格大于 0。
   - padding 位置允许行为权重和 `days_ago` 为 0。

2. 实现 `build_padding_mask`：
   - 返回 `torch.bool` Tensor。
   - mask shape 必须与 `item_ids` 一致。
   - `item_ids != padding_idx` 的位置为 `True`。
   - 不修改输入 Tensor。

3. 实现 `build_position_weights`：
   - `time_decay` 必须是有限非负数。
   - 使用 `torch.exp(-time_decay * days_ago)` 计算时间衰减。
   - 行为权重、时间衰减和 mask 必须通过逐元素运算组合。
   - padding 位置的最终权重必须严格等于 `0`。
   - 返回 Tensor 的 shape、device 和浮点 dtype 应与 `behavior_weights` 一致。

4. 实现 `masked_weighted_pool`：
   - 校验 `item_vectors` 为三维，另外两个输入为二维。
   - 前两个维度必须匹配，且所有输入在同一 device。
   - 使用 `unsqueeze(-1)` 将位置权重变为 `[B, L, 1]`。
   - 对序列维度求和，得到 `[B, D]` 加权向量和。
   - 只对权重和大于 0 的用户执行除法。
   - 空历史用户的输出向量必须严格为全零，不能包含 `NaN` 或 `inf`。
   - `has_history` 表示每行是否至少包含一个有效位置。

5. 实现 `BatchUserEncoder.forward`：
   - 先调用 `validate_batch`。
   - 依次调用 mask、位置权重和 embedding 查询逻辑。
   - 再调用 `masked_weighted_pool`，不要在 `forward` 中重复实现池化公式。
   - 返回字典时额外加入 `position_weights` 和 `valid_mask`，便于调试。

6. 用断言完成自检：
   - `user_vectors.shape == (4, 4)`。
   - `valid_mask.sum(dim=1)` 应等于 `[3, 2, 5, 0]`。
   - 所有 padding 位置的 `position_weights` 都应为 `0`。
   - 第 4 个用户的 `has_history` 应为 `False`，权重和为 `0`，用户向量为全零。
   - 所有输出都不应包含 `NaN` 或 `inf`。
   - 将 `time_decay` 设为 `0` 后，有效位置权重应等于原始行为权重。
   - 仅在序列尾部追加 padding 列，不应改变原有用户向量。
