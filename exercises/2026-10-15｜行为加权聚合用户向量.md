# 2026-10-15｜行为加权聚合用户向量

## 1. 任务背景

你正在用 Word2Vec 商品向量构造用户向量。直接对历史商品向量取平均虽然容易实现，但会把“很久以前的点击”和“刚发生的下单”视为同等重要；同时，线上数据还可能包含不在 Word2Vec 词表中的商品。

今天完成一个可复用的用户向量聚合流程：

1. 根据行为类型设置不同权重；
2. 使用时间衰减降低旧行为的影响；
3. 跳过词表外商品，并记录有效行为数；
4. 对有效商品向量做加权平均；
5. 用余弦相似度给候选商品打分，并排除用户已经交互过的商品。

本练习不依赖 Gensim，直接使用字典模拟 `model.wv`，便于集中练习列表遍历、向量聚合、shape 检查和边界处理。预计完成时间：20–30 分钟。

1. 将商品 ID 列表安全地映射为定长向量，并处理词表外商品。

3. 使用“加权向量和 ÷ 权重和”构造用户向量。

## 4. 待完成任务

1. 实现 `validate_embedding_table`：
   - 向量表必须非空，商品 ID 必须是非空字符串。
   - 每个向量必须是一维、非空、数值类型且全部有限。
   - 所有商品向量的 shape 必须完全一致。
   - 返回统一的 embedding 维度。

2. 实现 `validate_history`：
   - 将三个可迭代对象转为列表后检查，长度必须一致且非空。
   - 商品 ID 必须是非空字符串。
   - 每个行为必须存在于 `action_weights`。
   - `days_ago` 必须是非负整数。
   - 所有行为权重必须是有限正数。

3. 实现 `build_user_vector`：
   - `time_decay` 必须是有限非负数。
   - 按原始顺序遍历历史，词表外商品不参与聚合。
   - 单条有效行为权重使用
     `action_weight * np.exp(-time_decay * day)`。
   - 同一个商品重复出现时，每次行为都参与聚合。
   - 用有效权重总和归一化，而不是用有效行为条数做除数。
   - 如果没有任何有效商品，应抛出 `ValueError`。
   - 不修改历史列表、向量表或其中的原始向量。

4. 实现 `cosine_similarity`：
   - 两个输入必须是一维、shape 相同且全部有限。
   - 任一向量的 L2 范数为 0 时抛出 `ValueError`。
   - 返回 Python `float`，并将浮点误差导致的结果限制到 `[-1, 1]`。

5. 实现 `recommend_items`：
   - `top_k` 必须是正整数。
   - 使用集合进行历史商品过滤，但不能改变候选商品的 ID。
   - 对每个未交互商品调用 `cosine_similarity`。
   - 按“分数降序、商品 ID 升序”排序。
   - 候选不足 `top_k` 时返回全部候选，不补空值。

6. 用断言完成自检：
   - `embedding_dim` 应为 `4`。
   - `unknown_sku` 应出现在 `skipped_goods`，且不参与权重和。

   - 用户向量 shape 应为 `(4,)`，且所有元素有限。
   - 将 `time_decay` 设为 `0` 后，结果应只受行为权重影响。
   - 将所有有效行为权重同时乘以同一正数，用户向量应保持不变。
