# 2026-09-18｜构造LightFM稀疏交互矩阵

## 1. 任务背景

你已经能用 LightFM 训练推荐召回模型，但在真实任务中，模型收到的并不是用户行为明细表，而是一个形状为 `[用户数, 商品数]` 的稀疏交互矩阵。

今天聚焦模型训练之前最关键的数据准备环节：把点击、加购和下单事件转换成稳定的用户/商品整数索引，合并同一 `(user_id, item_id)` 的多次行为，并构造可供 LightFM 使用的 SciPy CSR 稀疏矩阵。

这一步常见的错误包括：

- 训练和预测阶段分别生成 ID 映射，导致同一个整数代表不同用户或商品。
- 同一用户对同一商品的多次行为没有聚合，矩阵中出现重复坐标。
- 只根据实际事件推断矩阵大小，遗漏暂时没有行为的用户或商品。
- 把原始字符串 ID 直接当作矩阵下标。
- 使用稠密二维数组，在真实规模下造成内存浪费。

本练习不训练模型。你需要自己完成映射、聚合和稀疏矩阵构造的关键逻辑，预计用时 20–30 分钟。
