## 1. 任务背景

昨天的 RRF 练习解决了多路召回结果如何融合，但融合后的候选集仍需要精排。若把每个商品独立当作二分类样本训练，模型只学习单个商品的点击概率，没有直接优化“同一次请求中，正反馈更高的商品应排在前面”。

ListMLE 是一种列表式排序损失。对于一组候选商品，先按真实相关性从高到低得到目标排列；在排列的第 `i` 个位置，模型应从剩余候选中给目标商品更高的概率。本题使用以下单列表损失：

```text
loss = mean_i(logsumexp(scores[i:]) - scores[i])
```

不同请求的候选数量不同，因此 batch 中使用 padding 和布尔 mask。你需要保证：

- padding 商品不参与目标排列、分母或评估；
- 相关性相同时保持原始候选顺序；
- 使用 `logsumexp` 或 `logcumsumexp`，不能直接计算指数和再取对数；
- 每个列表先按有效商品数取平均，再对 batch 取平均，避免长列表权重更大；
- 在评估 Top-1 时，padding 即使分数极高也不能被选中。

3. 实现 ListMLE 核心逻辑：
   - 每个列表只提取 `mask=True` 的元素；
   - 按相关性降序稳定排序，相关性并列时保持原顺序；
   - 对排序后的模型分数计算后缀 `logsumexp`；
   - 禁止使用 `exp().sum().log()`；
   - 每个列表对有效位置取平均；
   - 最终对列表损失取 batch 平均；
   - 保持计算图，不能把中间结果转换成 Python 数值。
